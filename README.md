# Домашнее задание 1. HTTP-сервис

**Предметная область:** Информационная система управления спортивным залом (фитнес-клубом).

## Архитектура и предметная область

### Связанные ресурсы:
1. **Клиент (`Client` / `/api/clients`)**:
   - `id`, `fullName`, `phone`, `email`, `birthDate`, `status` (`ACTIVE`, `BLOCKED`), `createdAt`, `updatedAt`.
2. **Абонемент (`Membership` / `/api/memberships`)**:
   - Связан с клиентом через `clientId`.
   - Поддерживает 3 типа абонементов с различающимся поведением:
     - `UNLIMITED` — безлимитные посещения в течение периода действия; поддерживает заморозку (`freeze`) с автоматическим продлением срока действия при разморозке (`unfreeze`). Продление ограничено фактически запрошенным сроком заморозки и суммарным лимитом 30 дней.
     - `VISIT_BASED` — абонемент с фиксированным количеством посещений (`totalVisits`, `remainingVisits`); каждое посещение списывает 1 визит, при 0 статус автоматически переходит в `EXPIRED`; заморозка запрещена бизнес-правилом.
     - `DAYTIME` — дневной безлимитный абонемент, действующий строго в интервале с 07:00 до 17:00 (при попытке входа в другое время вход отклоняется с кодом 422).
3. **Посещение (`Visit` / `/api/visits`)**:
   - Связывает клиента и абонемент.
   - Хранит дату/время входа, выхода, статус (`IN_PROGRESS`, `COMPLETED`) и номер выданного шкафчика (`lockerNumber`).

### Бизнес-операции (не сводящиеся к CRUD):
- **Вход в зал (`POST /api/memberships/{id}/check-in`)**:
  - Проверяет активность клиента (заблокированные клиенты не допускаются).
  - Проверяет отсутствие текущего незавершенного посещения (клиент не может зайти дважды).
  - Проверяет условия абонемента (сроки, активность, лимит посещений, временной интервал).
  - Выделяет свободный шкафчик из диапазона `L-101`–`L-200` (либо проверяет запрошенный `preferredLocker`, который строго должен принадлежать пулу шкафчиков `L-101`–`L-200`).
  - Для абонемента с визитами уменьшает счетчик и при исчерпании переводит статус в `EXPIRED`.
- **Выход из зала (`POST /api/visits/{id}/check-out`)**:
  - Завершает визит, фиксирует время выхода и освобождает шкафчик.
- **Заморозка абонемента (`POST /api/memberships/{id}/freeze`)**:
  - Доступна только для безлимитных типов; запрещена для визитных абонементов (возвращает 422).
  - Проверяет лимит заморозки (не более 30 дней суммарно).
  - Запрещает заморозку, если клиент прямо сейчас находится в зале.
- **Разморозка абонемента (`POST /api/memberships/{id}/unfreeze`)**:
  - Переводит статус в `ACTIVE` и продлевает дату окончания на фактически использованное число дней, но не более запланированного периода заморозки.
- **Блокировка/разблокировка клиента (`POST /api/clients/{id}/block`, `unblock`)**.
- **Аннулирование абонемента (`POST /api/memberships/{id}/cancel`)**.

### Фильтрация списков:
- `GET /api/clients?query=...&status=...` (поиск по имени, телефону, email, фильтр по статусу).
- `GET /api/memberships?clientId=...&type=...&status=...` (фильтр по клиенту, типу абонемента, статусу).
- `GET /api/visits?clientId=...&status=...` (фильтр по клиенту и статусу визита).

### Обработка ошибок и надёжность:
- `400 Bad Request` — некорректный JSON, JSON `null`, пустые обязательные поля, некорректный формат дат или недопустимый номер шкафчика.
- `404 Not Found` — обращение к несуществующему ресурсу.
- `405 Method Not Allowed` — неподдерживаемый HTTP-метод с заголовком `Allow`.
- `409 Conflict` — попытка повторного входа в зал, удаление клиента с активным посещением, повторная заморозка и т.д.
- `422 Unprocessable Entity` — нарушение правил предметной логики (заморозка визитного абонемента, исчерпание визитов, превышение лимита заморозки, дневной абонемент вне интервала).
- `500 Internal Server Error` — перехват непредвиденных исключений без падения сервера.
- **Конкурентная безопасность**: операции изменения состояния предметной области защищены единым глобальным монитором доменного слоя (`DomainLock`), предотвращая race conditions между проверкой визитов и удалением абонементов/клиентов.

## Запуск проекта

1. Запуск тестов:
```bash
mvn test
```

2. Запуск сервиса:
```bash
mvn spring-boot:run
```

3. Запуск тестов curl:
```bash
bash requests.sh
```
